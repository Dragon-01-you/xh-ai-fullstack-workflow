# Phase 0 · 需求理解 + 问题证伪

> 先弄懂“给谁、解决什么、边界在哪”；**这一步禁止聊技术方案**。
> 需求没理解就选型/搭环境/写测试，后面全是空转。

## 七问（写进 `REQUIREMENTS.md`）

1. **谁**：具体到一个人（名字/角色），不是“用户”。
2. **问题**：他在什么场景、卡在哪、现在怎么凑合？
3. **目标**：这一版做到什么算成功？（可观察）
4. **约束**：时间、钱、技术、地区、账号、合规。
5. **不做什么**：这一版明确不碰的范围 + 安全红线。
6. **成功指标**：上线后看哪个数？
7. **真实用户证据**：截图 / 聊天记录 / waitlist / 1 块钱付款（放 `evidence/requirements/`）。

## 步骤

1. 填 `templates/REQUIREMENTS.md`，七问都要有答案。
2. 找 1 个真实的人聊一次（不是问卷）。
3. 做一次最便宜的证伪实验（给 1 个人看图/假页面/发消息）。
4. 实验失败 → **停**，换问题；不许进入 Phase 1。

## 机器闸门

```bash
node gates/gate-requirements.mjs --file REQUIREMENTS.md
# 检查：七问标题齐全 + evidence/requirements/ 至少一个证据文件
# 产物：.gates/requirements.json
```

## 人的闸门

- 你能不看稿说出：谁、什么行为、什么信号放弃吗？
- 那个人真的回应过你吗？（不是“我觉得他会用”）

## 失败分支

- 找不到真实用户 → 先做内容/社群验证，别做产品。
- 实验失败 → 回 Phase 0 换问题；不许用“再加个功能”掩盖。

## 时间盒

45–90 分钟。超时不是继续，是缩小问题。

## 手工版

拿一张纸写七问；找一个人发消息；截图存档。
