# Phase 1 · 技术选型

> 需求清楚后，**先选栈，再装环境**。选错栈，环境白搭；选型不是“用我熟悉的”，是“匹配需求和约束”。

## 输入

- `REQUIREMENTS.md`（谁/问题/目标/约束/不做什么）
- 部署约束：地区（国内/国外）、支付方式、实名/备案、预算、是否需要常驻/数据库/GPU

## 步骤

1. **列约束**：先从需求里抄出硬约束（不是喜好）。
2. **列 2–3 个候选栈**：每个写清运行时、数据库、部署方式、代价。
3. **用维度评估**：交付速度 / 运行成本 / 部署难度 / 维护成本 / 生态 / 风险。
4. **做选择 + 写代价**：选哪个、为什么、放弃哪个、什么情况下改选。
5. **写 ADR**：`decisions/0001-stack.md`。
6. **核对部署前置**：支付/实名/域名/备案/运行时，缺的能不能补。
7. 如果选不出来：做 30–60 分钟 **selection spike**，只回答“哪个能跑通”，代码删掉，结论写进 `STACK.md`。

## 输出

- `STACK.md`（需求约束 / 候选方案 / 评估维度 / 选择 / 代价 / 何时改选）
- `decisions/0001-stack.md`

## 机器闸门

```bash
node gates/gate-stack.mjs --file STACK.md
# 检查：六个标题齐全 + 至少 2 个候选方案
# 产物：.gates/stack.json
```

## 人的闸门

- 你能说出“为什么不选另外两个”吗？
- 部署约束（地区/支付/实名/备案/运行时）真的能满足吗？
- 选型里有没有“因为我只会这个”？

## 失败分支

- 候选都跑不通 → 回 Phase 0 缩小目标。
- 选型卡住 → 30–60 分钟 spike；代码删掉，只留结论。
- 选型后发现部署条件不满足 → 回 Phase 1 重选，不许硬上。

## 时间盒

45–90 分钟。
