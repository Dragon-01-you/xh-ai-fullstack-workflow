# Phase 3 · 写规格（spec）

> 目标：把“要做什么”写成**可手工验收**的一页纸。验收写不出来 = 需求没想清，不许写代码。

## 必填段落（`templates/SPEC.md`）

1. **问题**：谁、什么场景、现在怎么凑合。
2. **用户故事**：S1…Sn，每条一个场景。
3. **验收**：3–5 条，必须含**失败路径**；每条能 5 分钟内手工做。
4. **不做什么**：范围排除 + 安全红线（分开写）。
5. **失败模式**：输入错 / 依赖挂 / 重复提交。
6. **前置条件**：账号、支付、实名、域名/备案、运行时（来自 Phase 0/1/8）。
7. **学习点**：这一版要学到什么。

## 机器闸门

```bash
node gates/gate-spec.mjs --file SPEC.md
# 检查：五个必填标题 + 验收 ≥3 条 + 至少一条失败
# 产物：.gates/spec.json
```

## 人的闸门

- 把 spec 读给一个**真实用户**听，问他：“这是你想要的吗？”
- 把回答记到 `evidence/spec/`。

## 失败分支

- 验收写不出来 → 回 Phase 0，缩小问题。
- 范围太大 → 只留第一版能上线的最小切片。
- 用户听不懂 → 改人话，不改需求。

## 时间盒

1–2 小时。

## 手工版

拿一张纸，按上面七段写；找一个人读一遍。
