# Phase 8 · 部署 / 回滚

> 目标：让别人能访问；并且**你能把它退回去**。

## 部署前：外部环境

先过一遍（缺一项先补，不要边部署边发现）：

- 账号 / 登录态
- 支付方式（外币卡 vs 微信/支付宝）
- 实名认证
- 域名 / ICP 备案（测试域名可先用）
- 运行时匹配（Node 常驻 / 静态 / 容器）

平台事实看 `platforms/<name>.md`；顶部 `last_verified` 超过 90 天 → 先复核。

## 部署步骤

1. 选平台（2–3 个选项 + 代价，人拍板）。
2. 配环境变量（`.env.example` 对应到平台）。
3. 部署；跑 `gate-http` 验证外网。
4. 写 `RUNBOOK.md`：启动/停止/看日志/回滚/常见故障。
5. **回滚演练**：假装新版本坏了，按 runbook 退回上一版，计时。

## 风险分级

| 级别 | 例子 | 规则 |
|---|---|---|
| 低 | 文案/样式 | 可自动部署 |
| 中 | 接口/数据库迁移 | 人工确认 + 备份 |
| 高 | 认证/支付/生产数据/密钥 | 人工确认 + 回滚预案 + 双人复核 |

## 机器闸门

```bash
node gates/gate-http.mjs --url https://<your-domain>/health --expect-status 200
node gates/gate-http.mjs --url https://<your-domain>/ --expect-status 200 --expect-text "<标题关键词>"
# .gates/http.json
```

> 只查 200 会放过白屏；`--expect-text` 检查页面标题/关键字。

## 人的闸门

- 外网打开一次（手机）。
- 用 `--expect-text` 检查页面标题/关键字，确认不是白屏 200。
- 按 runbook 回滚一次（演练）。
- 高风险变更有人复核。

## 失败分支

- 外网 500 → 先看平台日志，别改代码。
- 没有回滚方案 → 不许上线。
- 测试域名当正式域名 → 停，先备案或换测试策略。

## 时间盒

1–3 小时（不含备案等待）。
