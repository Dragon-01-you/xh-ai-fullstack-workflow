# 07 · 双向螺旋：每一步的「小白版 + 专业版」

> 用法：带人做项目时，先讲**小白版**建立画面，再讲**专业版**对齐术语，最后落到**对应 skill / 动作**。每步一个循环，十个循环走完就是整条流程。
>
> 为什么叫“双向螺旋”：
> - 只讲小白版：听得懂，但做不对（没有术语、没有边界）；
> - 只讲专业版：显得专业，但听不进去；
> - 螺旋：**画面 → 术语 → 行动 → 下一层**，一圈比一圈深。

---

## Phase 0 · 开工对话

**小白版**

- 比方：装修前先问“给谁住、几口人、预算多少、什么时候住”。不问清楚，后面全白干。
- 你要做的 3 步：
  1. 这次要“东西”还是“能力”？（只要能用，还是我要学会）
  2. 用一句话说：帮谁、解决什么？
  3. 真实用户是谁？每天能给多少时间、做几周？
- 一句话记住：**先定“为什么做、给谁做、做多久”，再动手。**

**专业版**

- 这一步定的是：目标（outcome）、范围（scope）、干系人（stakeholder）、约束（constraints）、成功指标（success metric）。
- 关键区分：**交付物**（能跑的东西）vs **能力**（你能独立再做一遍）；两者都要，但顺序不同。
- 常见坑：把方案当需求（“用 Redis”不是需求）；没有真实用户；时间预算拍脑袋。
- 产出：一页 brief（四问答案）。

**对应 skill**

- 调用：`grilling`（访谈）或 `grill-with-docs`（访谈 + 术语表/ADR）。
- 话术：「用 grilling 访谈我：每轮 frontier 提问，事实你查，决策我拍板；一次只问一个二选一。」
- 闸门：四问答完才开工。

## Phase 1 · 搭环境 / 护栏

**小白版**

- 比方：开工前先搭工棚、备灭火器、在墙上贴“这里不能动”。
- 你要做的 3 步：
  1. **存档点**：git——每做完一个能跑的版本存一次档，做坏了能回去。
  2. **一键检查**：`npm run check`——出门前摸一下钥匙、手机、钱包。
  3. **门卫**：提交拦截——`.env`、密钥、数据、依赖，不许进仓库。
- 再加三张纸：给 AI 的地图（`AGENTS.md`）、交接班便条（`PROGRESS.md`）、钥匙清单（`.env.example`）。
- 一句话记住：**先有工地，再让 AI 进场。**

**专业版**

- git：内容寻址的版本图；commit 是快照；`git reset --hard` 回滚（不可逆，先确认）。
- `npm run check`：确定性验证门禁（语法 + 测试；以后加 lint/类型/安全）。
- pre-commit hook：客户端钩子，`guard-staged.js` 拦 `.env`、`node_modules`、`data/`、数据库/私钥/密钥模式；`git config core.hooksPath .githooks` 启用。
- `AGENTS.md`：<100 行，只放项目地图/命令/红线/学习动作；`CLAUDE.md` 一行指向它，避免两份规则。
- `PROGRESS.md`：三行（做通/卡在/明天第一条命令），解决“隔天从零解释”。
- 常见坑：只写 `.gitignore` 不验证；hook 没启用；AGENTS.md 写成大百科。
- 产出：项目骨架 + 绿的 check。

**对应 skill**

- 调用：`writing-for-agents`（写 AGENTS/CLAUDE 的规范）；其余用本 skill 的 `scripts/`。
- 话术：「用 writing-for-agents 的规范写 AGENTS.md，<100 行，只放地图/命令/红线。」
- 闸门：`npm run check` 绿；故意 `git add .env` 会被拦。

## Phase 2 · 扫描

**小白版**

- 比方：医生先量身高体重血压，再开药。先看你是什么项目，再谈怎么部署。
- 你要做的 3 步：
  1. 看文件夹里有什么（只看名字和 `package.json`，不读你代码内容）；
  2. 判断你是“宣传册 / 前店后厨 / 连体餐车 / 24 小时值班保安 / 重型炼丹炉”；
  3. 标风险：前端藏钥匙、本地存数据、GPU 模型。
- 一句话记住：**先知道“我是什么项目、需要什么运行时”。**

**专业版**

- 代码形态：A 纯静态/SPA、B 前后端 API、B+ 同构元框架（Next/Nuxt/Streamlit/Gradio）、C 长连接/Bot/定时、D GPU 模型、E 微服务（劝退）。
- 数据状态：`none` / `local-file`（SQLite、uploads）/ `cloud-db`（pg、Supabase）。
- AI 形态：`none` / `api`（只有 SDK）/ `gpu-model`（权重文件）。
- 三条保命检查：`FRONTEND_SECRET`、`LOCAL_STATE`、`GPU_MODEL`。
- 配置扫描：`.env.example` 键名、`.nvmrc`、锁文件、已有部署配置。
- 常见坑：把 Serverless 当代码形态；漏掉本地 SQLite；把“前端项目”当全栈。
- 产出：项目画像 JSON。

**对应 skill**

- 调用：本 skill 的 scanner / `npm run scan` / `npm run plan`。
- 话术：「按 02-scan-and-prerequisites 的字段扫描这个目录，输出 JSON，不读源码正文、不联网。」
- 闸门：能说出“我是什么项目、需要什么运行时”。

## Phase 3 · 前置条件

**小白版**

- 比方：出国前先看护照、签证、机票、银行卡；缺哪样先补，不然到了机场也上不了飞机。
- 你要做的 3 步：
  1. 根据扫描结果，列出“你这类项目上线需要什么”；
  2. 对照你有啥：浏览器/账号/支付/实名/域名/运行时；
  3. 没有的，先补或先查（实名入口、免费额度、测试域名），补完再推荐。
- 一句话记住：**先看“你有没有资格上线”，再谈方案。**

**专业版**

- 六项：浏览器+控制通道、账号登录态、支付方式（外币卡 vs 微信/支付宝）、实名认证、域名/ICP 备案、运行时匹配（Node 常驻 + SQLite ≠ 纯静态）。
- 国内外取舍：国外多要外币卡；国内要实名 + 微信/支付宝，正式域名要 ICP。
- 缺项处理：先补前置，再推荐；不能“先推荐、后翻车”。
- 产出：前置条件表（有/没有/怎么补）。

**对应 skill**

- 调用：`research`（查官方价格/政策/备案）、`wizard`（账号/实名/面板向导）、`to-questionnaire`（需要问别人时）。
- 话术：「用 research 查 CloudBase 免费额度和实名要求，只引官方来源；用 wizard 生成注册/实名向导。」
- 闸门：每项有结论，缺的不能推荐。

## Phase 4 · 需求 / spec

**小白版**

- 比方：装修前写“验收单”：给谁住、要什么、怎么算合格、哪些不做、坏了怎么办。
- 你要做的 3 步：
  1. 写一句闭环：谁 → 打开哪 → 做什么 → 看到什么 → 数据怎么变；
  2. 写 3–5 条能手工验收的标准（至少一条失败路径）；
  3. 写“不做什么”和“失败长什么样”。
- 一句话记住：**验收写不出来，就是没想清楚，不许写代码。**

**专业版**

- 用户故事（S1…Sn）、验收标准（Given-When-Then/可手工执行）、Out of scope、失败模式（输入错/依赖挂/重复）。
- spec 一页纸，不写实现细节；验收是“行为级”，不是“接口返回 200”。
- 术语：`GLOSSARY.md`（词表）、ADR（难逆/意外/真取舍才写）。
- 常见坑：只写 happy path；把方案写进需求；范围不冻结。
- 产出：一页 spec。

**对应 skill**

- 调用：`grill-with-docs`（访谈 + 术语/ADR）→ `to-spec`（综合成 spec）+ `domain-modeling`。
- 话术：「先 grill-with-docs 澄清术语和取舍，再 to-spec 生成 spec；验收由我改。」
- 闸门：验收可手工执行；写不出来就不写代码。

## Phase 5 · 架构

**小白版**

- 比方：画“水管图”：水从哪来、经过哪、存哪、从哪出去；每个零件负责什么、不负责什么。
- 你要做的 3 步：
  1. 画数据流：页面 → 接口 → 业务 → 存储 → 返回；
  2. 列模块：每个模块一句话职责 + **不负责什么**；
  3. 定接口/表/在哪测（seam）。
- 一句话记住：**能指着图讲清楚，才算懂。**

**专业版**

- 模块（module）= 接口 + 实现；深模块 = 小接口 + 大实现；seam = 接口所在的位置；adapter = 在 seam 上满足接口的具体实现。
- 接口契约：输入/输出/错误码/幂等；数据模型：表/字段/约束/为什么。
- 设计取舍写进 ADR：选项/我选/理由/何时改选。
- 常见坑：浅模块（接口和实现一样复杂）；没有 seam；数据模型只写字段不写为什么。
- 产出：一页架构图 + ADR。

**对应 skill**

- 调用：`codebase-design`（模块/接口/seam 词汇）、`prototype`（设计问题纸上想不清时做一次性原型）。
- 话术：「用 codebase-design 审模块深度和 seam；这个状态模型用 prototype 做个一次性原型验证。」
- 闸门：能指着图讲清数据从哪来到哪去。

## Phase 6 · TDD

**小白版**

- 比方：先出考卷，再让考生答题；先写“什么算对”，看它会不会红，再让 AI 写。
- 你要做的 3 步：
  1. 选在哪测（seam）；
  2. 写 3–5 条测试，跑一下——看它红；
  3. 让 AI 写实现变绿，再故意改坏一行，看测试会不会红。
- 一句话记住：**红得对，绿得真。**

**专业版**

- 红 = 失败测试；绿 = 通过；先写测试再实现；一次一个行为。
- 对的红（功能不存在）vs 错的红（语法/路径/环境）；假测试四种（废话断言、Mock 被测对象、改测试预期、测实现细节）。
- 破坏实验（mutation test）：改坏代码，测试必须红；否则测试是假的。
- 3-2-1 配比：3 纯函数 + 2 接口/安全 + 1 手工 E2E。
- 常见坑：一次写十个测试；先写实现后补测试；为覆盖率写测试。
- 产出：测试 + 红绿记录 + 破坏实验记录。

**对应 skill**

- 调用：`tdd`（红绿循环/好测试/反模式）、`diagnosing-bugs`（卡住时）、`code-review`（实现后）。
- 话术：「调用 tdd：先确认 seam，再写测试；红得对再实现；卡住用 diagnosing-bugs。」
- 闸门：红得对、绿得真、破坏实验能抓住。

## Phase 7 · 实现

**小白版**

- 比方：让 AI 一次做一小步；每步先报“我要改哪、为什么”；你只看三样：接口、数据流、有没有多做。
- 你要做的 3 步：
  1. 看它 BEFORE（意图/改哪层/对应哪条验收/预期）；
  2. 批准后让它小步做；
  3. 只看接口签名、数据流、范围有没有扩大。
- 一句话记住：**一次一测试，不顺手加戏。**

**专业版**

- RUNLOG：BEFORE（意图/文件/对应验收/预期）→ AFTER（实际/差异/下一步选项）。
- 最小 diff；不顺手重构、不加未来功能；超范围写入 BACKLOG。
- 人审三样：接口签名、数据流、范围；不逐行读。
- 阶段边界：`handoff` / `/clear` / `/compact` 按 ask-matt 的 PHASE-BOUNDARIES 决定。
- 产出：代码 + RUNLOG。

**对应 skill**

- 调用：`implement`（每 ticket）或 `implement-spec`（整 spec）+ `handoff`（阶段边界）。
- 话术：「用 implement 做这个 ticket；阶段结束用 handoff 写交接文件。」
- 闸门：不超 spec 范围。

## Phase 8 · 验收

**小白版**

- 比方：自己上手用一遍，不看代码；截图为证；四样对齐：需求、测试、代码、线上。
- 你要做的 3 步：
  1. 按 spec 验收项逐条手工执行；
  2. 留证据（截图/curl 输出/时间）；
  3. 填 TRACE：需求 ↔ 测试 ↔ 代码 ↔ 手工证据 ↔ 线上。
- 一句话记住：**“测试通过”不算，你亲手用过才算。**

**专业版**

- 行为验收（不是实现验收）；TRACE 五列；四样齐才算闭环。
- 失败先写 bug 报告（现象/复现/预期/怀疑哪层），再让 AI 诊断。
- `code-review` 双轴：Standards（规范）+ Spec（是否实现了需求）；两轴分开报告。
- `wait-what`：报告看不懂，让它用大白话重讲。
- 产出：验收证据 + TRACE。

**对应 skill**

- 调用：`code-review`（双轴）、`wait-what`（听不懂时）。
- 话术：「用 code-review 双轴审 diff；报告我看不懂时用 wait-what 重讲。」
- 闸门：四样齐才算完成。

## Phase 9 · 部署

**小白版**

- 比方：先看护照签证（前置），再买票（配置），再登机（执行），最后确认到了（外网验收）。
- 你要做的 4 步：
  1. 确认六项前置都满足；
  2. 生成部署配置/步骤；
  3. 登录、授权、付款（只有人能做的）；
  4. 外网打开：`/health` 200 + 页面标题对。
- 一句话记住：**外网能打开，才算上线。**

**专业版**

- 部署拓扑：运行环境/入口/环境变量/数据在哪/日志看哪。
- 测试域名 vs 自定义域名：国内正式域名要 ICP；测试域名会弹风险提醒。
- 平台：CloudBase 静态托管（前端）/ 轻量服务器（Node+SQLite）/ 云托管（Docker）/ Render（外币卡）。
- 常见坑：无头浏览器、代付、上传源码、测试域名当正式域名。
- 产出：公网 URL + 验收证据。

**对应 skill**

- 调用：`wizard`（账号/密钥/面板）、`research`（官方部署文档/价格）。
- 话术：「用 wizard 生成部署向导；用 research 查官方部署文档。」
- 闸门：外网 `/health` 200 + 标题正确。

## Phase 10 · 复盘

**小白版**

- 比方：考完试对答案：哪题错了、为什么、下次怎么改；只改一个点；写一张“错题卡”。
- 你要做的 3 步：
  1. 三问：哪是狗屎 / 为什么 / 我得到什么；
  2. 只留一个明天要修的点；
  3. 写一张洞见卡（一句话/机理/可执行/边界）。
- 一句话记住：**说不出“哪不好、为什么”，这轮就没跑完。**

**专业版**

- 复盘对象是“环境”，不是“代码”：导航指针、自动检查、编码规范、steering 文件、工具。
- 洞见卡四要素；learning record 只记证据（不记流水账）。
- 写作：`writing-fragments`（攒碎片/leading word）→ `writing-beats`（节拍）→ `writing-shape`（成文）。
- 每日输出：做了什么 / 小白版 / 专业版 / 一个坑 / 一句可迁移 / 明天验证。
- 产出：改进项 + 洞见卡 + 当日输出。

**对应 skill**

- 调用：`retro`（复盘环境）、`teach`（learning record）、`writing-fragments` / `writing-beats` / `writing-shape`（写洞见/文章）。
- 话术：「用 retro 复盘这次会话的环境；用 teach 记 learning record；用 writing-* 写洞见。」
- 闸门：说得出“哪不好、为什么”，并留下一个明天要修的点。
